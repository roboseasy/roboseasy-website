# A-Go(LeKiwi) 유선 연결

A-Go(LeKiwi)의 두뇌는 라즈베리파이입니다. 이 라즈베리파이에는 모니터도 키보드도 붙어 있지 않습니다. 이렇게 화면 없이 쓰는 컴퓨터를 **헤드리스(headless)** 라고 부르며, 네트워크로 접속해 다룹니다. 처음 접속은 로봇 와이파이(AP)로 하면 되지만([처음 접속하기](/docs/a-go/first-connection)), 랜선 하나로 PC 와 직접 잇는 길도 있습니다. 유선은 와이파이 설정이 꼬였을 때도 늘 열려 있는 **비상 통로**입니다.

> 🎯 **학습 목표**
>
> - 유선 연결이 필요한 때를 설명할 수 있다.
> - PC 의 인터넷 공유 기능으로 로봇에 주소와 인터넷을 함께 줄 수 있다.
> - 네트워크 스캔으로 화면 없는 로봇의 주소를 찾을 수 있다.
> - SSH 와 웹 화면으로 접속하고, 호스트 키 확인 메시지의 뜻을 설명할 수 있다.

---

## 1. 왜 랜선으로 직접 연결할까?

### 1.1. 유선이 쓰이는 때

| 상황 | 설명 |
|---|---|
| 와이파이 설정이 꼬였을 때 | 공유기 이름 · 비밀번호를 잘못 넣었거나 AP 비밀번호를 잊어 와이파이로 붙지 못할 때, 랜선으로 들어와 고칩니다 |
| 와이파이 모드를 바꿀 때 | 와이파이로만 붙어 있으면 AP ↔ 공유기 전환 순간 접속이 끊깁니다. 랜선이 있으면 그동안에도 계속 볼 수 있습니다 |
| 노트북 인터넷을 쓰면서 로봇도 다룰 때 | 노트북의 와이파이는 인터넷에 그대로 두고, 로봇은 랜선으로 잇습니다 |
| Physical Labs 로 처음 로봇을 붙일 때 | 앱의 연결 방식 기본값이 `이더넷 직결` 입니다 ([Physical Labs 연결](/docs/a-go/physical-labs-setup)) |

로봇의 와이파이 · AP 를 바꾸는 스크립트는 어느 것도 **유선(eth0) 설정을 건드리지 않습니다.** 그래서 와이파이가 어떤 상태든 랜선으로는 늘 들어올 수 있습니다.

### 1.2. PC 인터넷 공유

랜선을 PC 와 로봇에 꽂기만 해서는 로봇이 주소를 받지 못합니다. PC 의 **인터넷 공유(Internet Sharing)** 기능을 켜면 PC 가 작은 공유기 역할을 하며 로봇에 주소를 나눠 줍니다.

| 역할 | 우분투 | 윈도우 | 설명 |
|---|---|---|---|
| PC (이더넷 포트) | `10.42.0.1` | `192.168.137.1` | 공유기의 게이트웨이처럼 동작 |
| 로봇 | `10.42.0.x` | `192.168.137.x` | PC 가 DHCP 로 자동 배정 |

로봇은 PC 를 거쳐 인터넷까지 쓸 수 있습니다. 이 방식을 NAT(Network Address Translation)라고 하며, 집 공유기가 여러 기기를 회선 하나로 내보내는 것과 같은 원리입니다.

> **정보** ℹ️ `INFO`
> <br>**윈도우 PC 에서도 유선 연결 · SSH · 웹 화면은 그대로 됩니다** 다만 Windows 판 Physical Labs(0.1.7)는 새 A-Go 를 아직 지원하지 않습니다. Physical Labs 로 로봇을 다루려면 Ubuntu 판을 씁니다.

## 2. 유선 연결 절차

### 2.1. [PC] 유선 인터넷 공유 세팅

#### 우분투

우분투 PC 에서 다음 순서로 설정합니다.

**설정(Settings) → 네트워크(Network) → 유선(Wired) → ⚙️ → IPv4 → `다른 컴퓨터에 공유`(Shared to other computers) → 적용(Apply)**

![우분투 네트워크 설정의 유선 항목과 톱니 버튼](/img/a_go/lekiwi-wired-connection-01.webp)

![유선 연결 창의 IPv4 탭에서 '다른 컴퓨터에 공유'를 고른 모습](/img/a_go/lekiwi-wired-connection-02.webp)

> **팁** 💡`TIP`
> <br>PC 이더넷에 `10.42.0.1` 이 붙었는지 `ip -4 addr` 로 확인할 수 있습니다. 이 주소가 보이지 않으면 공유 설정이 적용되지 않은 것이니 케이블을 뺐다 꽂거나 유선(Wired) 스위치를 껐다 켜 봅니다.

#### 윈도우 (관리자 권한 필요)

1. `Win + R` → **`ncpa.cpl`** 실행
2. **Wi-Fi** (인터넷이 들어오는 쪽) 우클릭 → **속성** → **공유** 탭
3. ☑ **"다른 네트워크 사용자가 이 컴퓨터의 인터넷 연결을 통해 연결할 수 있도록 허용"**
4. **홈 네트워킹 연결** 드롭다운 → **이더넷** 선택 (아래 그림처럼 드롭다운이 보이지 않으면 이 단계는 건너뜁니다)
5. 확인

> **경고** ⚠️ `WARN`
> <br>**방향을 헷갈리기 쉽습니다** 공유를 켜는 것은 **인터넷이 들어오는 Wi-Fi** 쪽이고, 드롭다운에서 고르는 것은 **로봇이 꽂힌 이더넷** 입니다. 반대로 하면 안 됩니다.

![윈도우 네트워크 연결 목록 — Wi-Fi 와 이더넷](/img/a_go/lekiwi-wired-connection-03.webp)

![Wi-Fi 오른쪽 클릭 메뉴의 속성](/img/a_go/lekiwi-wired-connection-04.webp)

![Wi-Fi 속성의 공유 탭에서 인터넷 연결 공유를 허용한 모습](/img/a_go/lekiwi-wired-connection-05.webp)

설정을 마쳤으면 이더넷 어댑터가 `192.168.137.1` 을 받았는지 `ipconfig` 로 확인합니다.

> **정보** ℹ️ `INFO`
> <br>**윈도우 인터넷 공유(ICS)에서 알아 둘 점**
>
> - ICS 대역은 `192.168.137.0/24` 로 **고정**입니다. 레지스트리로 바꿀 수 있지만 그대로 두는 것을 권합니다.
> - 재부팅 후 공유가 풀리는 경우가 있습니다. `SharedAccess` 서비스가 `Running` 인지 확인합니다.
> - 우분투에서 쓰던 주소(`10.42.0.x`)는 윈도우에서는 나오지 않습니다. `192.168.137.x` 가 정상입니다.

### 2.2. [로봇] 랜선 꽂고 전원 켜기

1. 랜선을 PC 의 이더넷 포트와 로봇 라즈베리파이의 이더넷 포트에 꽂습니다.
2. 로봇 전원을 켭니다. 이미 켜져 있었다면 그대로 둡니다 — 랜선을 꽂으면 로봇이 알아서 주소를 받습니다.
3. 로봇이 부팅을 마치고 주소를 받기까지 보통 30초~1분, 카드를 새로 구운 뒤 처음 켤 때는 1~2분쯤 걸립니다. 바로 다음 단계로 넘어가지 말고 잠시 기다립니다.

> **경고** ⚠️ `WARN`
> <br>새로 구운 카드의 첫 부팅 중에는 전원을 끊지 마세요. 카드 용량을 늘리는 중이라 카드가 손상될 수 있습니다.

### 2.3. [PC] 로봇 IP 찾기

로봇이 어떤 주소를 받았는지 알아야 접속할 수 있습니다. 화면이 없으니 직접 볼 수는 없고, 대신 PC 에서 **같은 네트워크에 누가 있는지** 확인합니다.

#### 우분투

`nmap` 으로 공유 대역(`10.42.0.x`)을 스캔합니다.

```bash
# 우분투
sudo apt update && sudo apt install -y nmap

nmap -sn 10.42.0.0/24
```

![nmap 결과 — PC(10.42.0.1)와 로봇(10.42.0.61) 두 대](/img/a_go/lekiwi-wired-connection-06.webp)

- `10.42.0.0/24` 는 `10.42.0.0` 부터 `10.42.0.255` 까지 256개 주소를 뜻합니다.
- `-sn` 은 포트 검사 없이 "살아 있는지"만 확인하는 옵션이라 빠릅니다.
- 결과에서 `10.42.0.1`(PC 자신)이 아닌 쪽이 로봇입니다. 위 예시에서는 `10.42.0.61` 입니다. 받는 주소는 PC 와 로봇마다 다르고, 다음에 다시 꽂으면 바뀔 수도 있습니다.

> **팁** 💡`TIP`
> <br>로봇이 여러 대 붙어 있으면 `sudo nmap -sn 10.42.0.0/24` 로 실행합니다. 관리자 권한으로 실행하면 MAC 주소와 제조사(Raspberry Pi)가 함께 표시되어 구분할 수 있습니다.

#### 윈도우

윈도우에서는 ARP 테이블에서 공유 대역(`192.168.137.x`)에 붙은 장치를 확인합니다. `192.168.137.1`(PC 자신)과 `.255`(브로드캐스트)를 제외한 주소가 로봇입니다.

```bat
:: 윈도우
arp -a -N 192.168.137.1
```

![arp 결과 — 192.168.137.145 가 로봇](/img/a_go/lekiwi-wired-connection-07.webp)

위 예시에서는 `192.168.137.145` 가 로봇입니다.

> **팁** 💡`TIP`
> <br>**이름으로도 붙어 볼 수 있습니다** 로봇은 `lekiwi01.local` 같은 이름을 같은 네트워크에 스스로 알립니다(로봇 번호를 바꿨다면 그 이름). 우분투나 최신 윈도우에서는 `ssh roboseasy@lekiwi01.local` 처럼 이름으로 접속될 수 있습니다. 안 되면 위처럼 주소를 찾습니다.

Ubuntu 판 Physical Labs 를 쓴다면 앱이 대신 찾아 줍니다. 로봇 설정의 `연결 방식` 을 `이더넷 직결` 로 두고 **🔍 찾기** 를 누르면, 공유 대역에서 로봇을 찾아 주소 칸을 채웁니다 ([Physical Labs 연결](/docs/a-go/physical-labs-setup)).

### 2.4. [PC] SSH 접속

**SSH(Secure Shell)** 는 네트워크 너머의 컴퓨터에 암호화된 터미널로 접속하는 표준 방법입니다.

```bash
ssh roboseasy@<로봇 IP>
```

위 예시라면 `ssh roboseasy@10.42.0.61` 을 입력합니다. 비밀번호는 **스페이스 한 번** 입니다.

![우분투에서 처음 SSH 접속 — 호스트 키 질문, 비밀번호, Ubuntu 환영 문구](/img/a_go/lekiwi-wired-connection-08.webp)

처음 접속하면 아래와 같은 질문이 나옵니다.

```text
The authenticity of host '10.42.0.61 (10.42.0.61)' can't be established.
ED25519 key fingerprint is SHA256:...
Are you sure you want to continue connecting (yes/no/[fingerprint])?
```

이것은 오류가 아닙니다. SSH 는 상대 컴퓨터의 **호스트 키 지문(fingerprint)** 을 기억해 두었다가, 다음에 같은 주소에서 다른 지문이 나오면 "누군가 중간에서 가로채는 것 아니냐"고 경고합니다. 처음 보는 로봇이니 `yes` 를 입력해 등록합니다.

접속되면 프롬프트가 `roboseasy@lekiwi01:~$` 처럼 바뀝니다 (`lekiwi01` 자리는 로봇의 호스트 이름입니다). 이제 입력하는 명령은 PC 가 아니라 **로봇 안에서** 실행됩니다.

윈도우에서도 명령 프롬프트에서 같은 방법으로 접속합니다. 주소만 `192.168.137.x` 대역입니다.

```bat
:: 윈도우
ssh roboseasy@192.168.137.145
```

![윈도우 명령 프롬프트에서 처음 SSH 접속 — 호스트 키 질문](/img/a_go/lekiwi-wired-connection-09.webp)

### 2.5. [로봇] 접속 확인

정말 로봇 안에 들어와 있는지 확인합니다.

```bash
hostname          # 로봇 이름 (처음에는 lekiwi01)
hostname -I       # 로봇이 가진 IP 목록 (유선 · 와이파이)
net_status        # 지금 켜진 네트워크 연결과 주소
uname -m          # aarch64 가 나오면 ARM 기반 라즈베리파이
```

`hostname -I` 에는 유선 주소와 함께 와이파이 주소(AP 모드면 `192.168.4.1`)도 나옵니다. 접속을 끊을 때는 `exit` 를 입력하거나 `Ctrl + D` 를 누릅니다.

### 2.6. [웹 화면] 웹 화면 열기

찾은 유선 주소로 웹 화면도 열 수 있습니다. 브라우저 주소창에 입력합니다.

```text
http://<로봇 IP>:8080
```

위 예시라면 `http://10.42.0.61:8080` 입니다. 처음 보이는 대시보드는 [처음 접속하기](/docs/a-go/first-connection)와 같습니다.

- 주소에 `http://` 와 끝의 `:8080` 이 꼭 있어야 합니다.
- 숫자 주소나 `.local` 이름으로 엽니다. 다른 이름(예: 공유기가 붙인 `lekiwi01.lan`)으로 열면 `이 주소로는 열 수 없습니다 …` 가 나오며 일부러 거절합니다.

## 3. [웹 화면] 유선과 와이파이를 함께 쓰기

랜선을 꽂은 채로 로봇은 와이파이(AP 또는 공유기)에도 붙어 있습니다. 웹 화면 **네트워크** 에서 두 연결을 한눈에 볼 수 있습니다.

![네트워크 화면 — 공유기 모드 와이파이와 유선 연결, 유선 접속 안내](/img/a_go/web-network.webp)

*이 로봇은 공유기 와이파이(`wlan0`)와 랜선(`eth0`, `10.42.0.170`)에 함께 붙어 있습니다.*

| 칸 | 보이는 것 |
|---|---|
| `지금 연결` | 와이파이 모드(`공유기 모드` / `AP 모드`), 호스트 이름, 와이파이 이름, 신호 |
| `유선 (이더넷)` | `케이블` (`연결됨 · eth0 · 1000 Mb/s` 또는 `케이블 없음 (eth0)`), `유선 주소`, `게이트웨이` (PC 주소) |
| `인터넷 경로` | 로봇이 인터넷에 나가는 길 (`유선 (eth0)` 이면 PC 를 거쳐 나갑니다) |
| 유선 안내 | `유선으로 접속: http://<유선 IP>:8080 · PC 에이전트는 --robot <유선 IP>` |
| `인터페이스` | `eth0` · `wlan0` 의 상태와 주소 |

- 유선 안내의 주소를 그대로 쓰면 됩니다. PC 에이전트도 이 주소로 붙일 수 있습니다 ([PC 에이전트 (리더암)](/docs/a-go/pc-agent)).
- 랜선이 꽂혀 있으면 와이파이 모드를 바꾸는 동안에도 유선 주소로 웹 화면이 끊기지 않습니다. 모드 전환은 [네트워크 (AP · 공유기)](/docs/a-go/lekiwi-wifi-static-ip)에서 다룹니다.
- 랜선을 뽑으면 유선 주소는 사라집니다. 그때는 와이파이 쪽 주소로 접속합니다.

## 4. 문제 해결

| 증상 | 확인할 것 |
|---|---|
| nmap 결과에 PC 만 나온다 | 로봇 부팅을 기다립니다 (첫 부팅은 1~2분). 랜선 양쪽 연결, 로봇 전원, PC 유선 설정이 `다른 컴퓨터에 공유` 인지 봅니다 |
| PC 유선에 `10.42.0.1` 이 없다 | 공유 설정을 다시 적용하고, 케이블을 뺐다 꽂거나 유선 스위치를 껐다 켭니다 |
| 윈도우에서 재부팅 뒤 로봇이 안 보인다 | 인터넷 공유가 풀렸을 수 있습니다. `SharedAccess` 서비스가 `Running` 인지, 공유 탭 체크가 남아 있는지 봅니다 |
| `Connection refused` | 아직 부팅 중일 수 있습니다. 30초 뒤 다시 시도합니다 |
| `Permission denied` | 비밀번호는 스페이스 한 번입니다. 사용자 이름 `roboseasy` 철자를 봅니다 |
| `REMOTE HOST IDENTIFICATION HAS CHANGED` | 카드를 새로 구웠거나, 같은 주소에 다른 로봇이 붙었습니다. 내 로봇이 맞다면 `ssh-keygen -R <로봇 IP>` 로 예전 기록을 지우고 다시 접속합니다 |
| SSH 는 되는데 웹 화면이 안 열린다 | 주소에 `http://` 와 `:8080` 이 있는지 봅니다. 로봇이 막 켜졌다면 잠시 기다립니다 |
| `이 주소로는 열 수 없습니다 …` | 숫자 주소(`http://10.42.0.61:8080` 등)나 `.local` 이름으로 엽니다 |
| 어제와 주소가 다르다 | 정상입니다. PC 가 꽂을 때마다 주소를 새로 나눠 줄 수 있습니다. 다시 찾습니다 |

---

## 5. 정리

- 헤드리스 로봇은 화면 대신 **네트워크 + SSH · 웹 화면** 으로 다룹니다.
- PC 인터넷 공유를 켜면 PC 가 공유기 역할(우분투 `10.42.0.1`, 윈도우 `192.168.137.1`)을 하고, 로봇은 같은 대역의 주소를 받습니다.
- `nmap -sn`(우분투) 또는 `arp -a`(윈도우)로 주소를 찾고, `ssh roboseasy@<로봇 IP>` 와 `http://<로봇 IP>:8080` 으로 접속합니다.
- 와이파이 스크립트는 유선을 건드리지 않으므로, 유선은 와이파이가 꼬였을 때의 비상 통로입니다.
