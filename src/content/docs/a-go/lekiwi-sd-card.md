# A-Go(LeKiwi) microSD 카드 굽기

A-Go(LeKiwi)의 두뇌인 라즈베리파이에는 PC와 달리 내장 저장장치가 없습니다. 운영체제부터 ROS 2 로봇 프로그램, 웹 화면까지 모든 것이 **microSD 카드** 한 장에 들어 있고, 라즈베리파이는 이 카드로 부팅합니다. RoboSEasy는 필요한 소프트웨어를 미리 설치해 둔 **카드 이미지**를 제공합니다. 이 페이지에서는 이미지를 내려받아 카드에 굽고, 로봇에 꽂아 첫 부팅을 마치는 것까지 안내합니다.

진행 순서는 다음과 같습니다.

1. **[PC]** 위의 이미지를 내려받고, 파일이 온전한지 확인합니다. (3절)
2. **[PC]** Raspberry Pi Imager로 이미지를 microSD 카드에 굽습니다. (4절)
3. **[로봇]** 구운 카드를 라즈베리파이에 꽂고 전원을 켜 첫 부팅을 기다립니다. (5절)
4. 다음 페이지 [처음 접속하기](/docs/a-go/first-connection)에서 로봇이 띄운 와이파이에 붙습니다.

## 1. 왜 이미지를 구워야 할까?

### 1.1. 이미지란?

**이미지**(image)는 카드 한 장의 내용을 통째로 파일 하나로 만든 것입니다. 운영체제, 설치된 프로그램, 설정 파일이 폴더 구조까지 들어 있어서, 이 파일을 다른 카드에 그대로 기록하면 똑같은 카드가 한 장 더 만들어집니다. 이렇게 기록하는 일을 **굽는다**(burn, flash)고 합니다.

일반 파일 복사와는 다릅니다. 이미지는 카드의 파티션 구조와 부팅 영역까지 포함하므로, 파일을 카드에 복사해 넣는 것이 아니라 **전용 도구로 카드에 기록**해야 합니다.

### 1.2. 이미지에 들어 있는 것

직접 설치하면 한 단계씩 시간이 걸리고 버전이 어긋나기 쉬운 것들이 이미 갖춰져 있습니다.

| 항목 | 내용 |
|---|---|
| 대상 보드 | Raspberry Pi 4 Model B (라즈베리파이 5에서는 시험하지 않았습니다) |
| 운영체제 | Ubuntu 24.04.4 LTS (라즈베리파이용 64비트) |
| 로봇 프로그램 | ROS 2 Jazzy와 LeKiwi 작업공간 `~/lekiwi_ws` — 바퀴 · 팔 모터, 카메라, 라이다, IMU, 지도 작성 · 자율 주행, Physical Labs 연결 노드 |
| 웹 화면 | `~/lekiwi_web_operator` — 로봇 전원을 켜면 저절로 뜹니다 (포트 `8080`). 브라우저로 상태를 보고, 로봇 기능을 켜고, 보정 · 조작 · 네트워크 설정을 합니다 |
| 네트워크 도구 | `~/lekiwi_net` — 와이파이 · AP 모드 전환 스크립트. 웹 화면과 Physical Labs가 이 스크립트를 씁니다 |
| LeRobot | 0.6.0 (`~/lerobot060_venv`) — 팔로워 팔 노드가 안에서 씁니다. 따로 실행할 일은 없습니다 |
| 로그인 계정 | `roboseasy` (비밀번호: 스페이스 한 번) |
| 이름 · 번호 | 호스트 이름 `lekiwi01`, 로봇(킷) 번호 1 |
| 처음 네트워크 | AP 모드 — 로봇이 와이파이 `lekiwi01`(비밀번호 `lekiwi01`)을 직접 띄웁니다 (5.3절) |

로봇의 `~/lekiwi_ws` · `~/lekiwi_net` · `~/lekiwi_web_operator` 폴더는 각각 같은 이름의 공개 저장소와 짝입니다. 카드에 모두 들어 있으므로 사용자가 따로 설치할 것은 없습니다. 구조가 궁금하면 [저장소와 구조](/docs/a-go/developer)를 봅니다.

반대로 **공유기(와이파이) 정보, 팔로워 팔 보정 · 접은 자세, 지도**는 들어 있지 않습니다. 로봇마다 다른 값이라 카드를 구운 뒤 직접 정합니다 (6절).

> **정보** ℹ️ `INFO`
> <br>**Physical Labs로 쓰려면 우분투판이 필요합니다** 이 로봇은 브라우저의 웹 화면과 Physical Labs 우분투(.deb)판(이 문서 기준 0.1.9)으로 씁니다. 윈도우판 최신 0.1.7은 새 A-Go(ROS 2 로봇)를 지원하지 않으므로, 윈도우 PC에서는 웹 화면으로 씁니다. 카드 굽기는 윈도우에서도 됩니다.

### 1.3. 예전 이미지와 달라진 점

예전 이미지(`lekiwi1017` 등)를 쓰던 로봇이라면 아래가 달라졌습니다.

| 항목 | 예전 이미지 | 새 이미지 (`lekiwi1027`) |
|---|---|---|
| 로봇 프로그램 | 로봇에서 LeRobot 호스트 스크립트(`~/start_lekiwi_host.sh`)를 직접 실행 | ROS 2로 바뀌었습니다. 웹 화면이나 Physical Labs의 **로봇 켜기**로 켭니다 |
| 처음 켰을 때 | 어느 와이파이에도 붙지 않아 랜선으로 먼저 접속 | 로봇이 와이파이(AP 모드)를 직접 띄웁니다. 랜선도 됩니다 |
| 와이파이 · 고정 IP | netplan 설정 파일, 홈 폴더의 `clone_init.sh` | 웹 **네트워크** 화면, Physical Labs, `~/lekiwi_net` 스크립트 |
| 카메라 | udev 별칭(`/dev/cam_front` 등)을 직접 만듦 | 카메라를 꽂은 USB 포트 자리로 정해집니다 ([카메라 연결](/docs/a-go/setup-cameraport)) |
| 파일 크기 | 약 3.1GB | 약 2.4GB |

예전 카드를 새 구조로 바꾸는 업데이트는 없습니다. 새 이미지로 다시 굽습니다. 굽기 전에 7.1절에서 옮겨 둘 것을 먼저 확인합니다.

> **경고** ⚠️ `WARN`
> <br>**예전 안내의 명령을 새 카드에서 쓰지 마세요** 호스트 스크립트 실행, netplan으로 와이파이 · 고정 IP 정하기 같은 예전 명령은 새 카드와 맞지 않습니다. 특히 netplan 방식의 와이파이 설정은 새 카드의 네트워크 관리(NetworkManager)와 부딪혀 와이파이가 꼬일 수 있습니다.

## 2. 준비물

| 준비물 | 설명 |
|---|---|
| **microSD 카드** | 16GB 이상(32GB 권장). Class 10 / U1 이상의 정품 카드를 사용합니다. 속도가 느리거나 정품이 아닌 카드는 굽는 도중 오류가 나거나 부팅이 불안정해지는 일이 잦습니다. microSD를 SD 어댑터에 끼워 쓴다면 어댑터의 잠금(LOCK) 스위치를 풀어 둡니다. |
| **카드 리더기** | PC에 microSD 카드를 꽂을 수 있는 USB 리더기 (노트북 내장 슬롯도 가능) |
| **PC** | 윈도우 10/11 또는 우분투. 내려받은 파일을 둘 여유 공간 3GB 이상 |
| **인터넷** | 약 2.4GB 파일을 내려받습니다 |
| **와이파이가 되는 노트북이나 휴대폰** | 첫 부팅 뒤 로봇이 띄운 와이파이에 붙어 확인합니다 ([처음 접속하기](/docs/a-go/first-connection)) |

이미지는 빈 공간을 줄여 8,644,932,096바이트(약 8.6GB)로 만들어 두었습니다. 처음 부팅할 때 카드 전체 크기만큼 자동으로 늘어나므로, 16GB·32GB·64GB 어느 카드를 써도 됩니다. 8GB 카드에는 들어가지 않습니다.

> **경고** ⚠️ `WARN`
> <br>카드의 기존 내용이 모두 사라집니다. 보관할 파일이 있다면 먼저 다른 곳에 복사해 둡니다. 로봇에서 쓰던 카드를 다시 굽는다면 7.1절을 먼저 봅니다.

### 3.2. 파일 확인 (권장)

2GB가 넘는 파일은 내려받는 도중 끊기거나 일부가 깨지는 일이 있습니다. 깨진 이미지로 카드를 만들면 부팅이 안 되거나 이상하게 동작하므로, 먼저 **SHA-256 해시**를 계산해 아래 값과 같은지 확인합니다. 해시는 파일 내용에서 계산한 지문과 같아서, 한 비트만 달라져도 전혀 다른 값이 나옵니다.

```text
38192ed1d02203154e52424d52f3781122dabbeb0a18ef1ad5a8fdabf929330d  lekiwi1027.img.gz
```

#### 우분투

브라우저가 파일을 저장한 다운로드 폴더에서 아래 명령을 실행합니다. `성공`(영어 화면은 `OK`)이 나오면 정상입니다.

```bash
# 우분투
cd "$(xdg-user-dir DOWNLOAD)"
echo "38192ed1d02203154e52424d52f3781122dabbeb0a18ef1ad5a8fdabf929330d  lekiwi1027.img.gz" | sha256sum -c
```

`xdg-user-dir DOWNLOAD` 는 다운로드 폴더의 위치를 찾아 줍니다. 한국어로 설치한 우분투에서는 이 폴더가 `~/Downloads` 가 아니라 `~/다운로드` 입니다. 다른 폴더에 받았다면 `cd` 로 그 폴더에 들어갑니다.

#### 윈도우

시작 메뉴에서 `cmd` 를 검색해 명령 프롬프트를 열고 입력합니다. 파일을 다른 폴더에 받았다면 경로를 바꿉니다.

```bat
:: 윈도우
certutil -hashfile "%USERPROFILE%\Downloads\lekiwi1027.img.gz" SHA256
```

2GB가 넘는 파일이라 계산이 끝날 때까지 수십 초 걸릴 수 있습니다. 출력된 64자리 값이 위와 같으면 정상입니다. 대소문자는 구분하지 않습니다.

값이 다르면 파일을 지우고 다시 내려받습니다. 두 번 받아도 계속 다르면 이 문서의 값이 오래된 것일 수 있으니, 굽지 말고 RoboSEasy에 문의합니다.

> **팁** 💡`TIP`
> <br>위 값은 이 페이지의 `lekiwi1027.img.gz` 전용입니다. 새 이미지가 올라오면 이 페이지의 링크, 파일 이름, 해시값이 함께 바뀝니다. 이 페이지에 적힌 이름과 다른 파일을 받았다면 비교하지 말고 RoboSEasy에 문의합니다.

## 4. [PC] microSD 카드에 굽기

굽기 도구로는 라즈베리파이 공식 도구인 **Raspberry Pi Imager**를 씁니다. 무료이고 우분투와 윈도우 모두에서 쓸 수 있으며, `.img.gz` 파일을 압축을 풀지 않고 바로 카드에 기록합니다.

### 4.1. Raspberry Pi Imager 설치

#### 우분투

터미널에서 설치합니다.

```bash
# 우분투
sudo apt update
sudo apt install -y rpi-imager
```

> **팁** 💡`TIP`
> <br>apt로 설치되는 버전(1.8.x)은 공식 사이트의 최신판(2.x)과 화면이 다릅니다. 4.2절에 두 화면의 버튼 이름을 함께 적었습니다. 공식 사이트의 **Download for Linux (x86_64)** 버튼으로 받은 AppImage를 쓰려면 받은 폴더에서 `chmod +x imager_latest_amd64.AppImage` 로 실행 권한을 준 뒤 실행합니다. `libfuse.so.2` 오류로 실행되지 않으면 `sudo apt install -y libfuse2t64` 를 먼저 설치합니다.

#### 윈도우

[라즈베리파이 소프트웨어 페이지](https://www.raspberrypi.com/software/)에서 **Download for Windows**를 눌러 설치 파일을 받아 실행합니다.

### 4.2. 카드에 굽기

> **정보** ℹ️ `INFO`
> <br>**Imager는 버전과 PC 언어에 따라 화면 문구가 다릅니다** 윈도우 설치 파일은 2.x(단계별 화면), 우분투 `apt` 버전은 1.8.x(버튼이 모여 있는 한 화면)입니다. 한국어 PC에서는 한국어로 표시되므로 아래 단계에 한국어 문구와 영어 문구를 함께 적었고, 2.x와 1.8.x가 다를 때는 구분해 적었습니다. 문구는 버전에 따라 조금 다를 수 있습니다.

1. microSD 카드 외의 USB 저장장치(외장 하드, USB 메모리)는 모두 뽑아 두고, 카드를 카드 리더기에 꽂아 PC에 연결합니다.
2. **Raspberry Pi Imager**를 실행합니다. 윈도우에서는 관리자 권한을 묻는 창이 뜨면 허용합니다. 우분투에서는 앱 목록의 **Imager** 아이콘(또는 터미널의 `rpi-imager` 명령)으로 실행하며, 쓰기를 시작할 때 로그인 암호를 묻는 창이 뜰 수 있습니다.
3. 장치 선택 단계(2.x 화면 제목 '라즈베리 파이 장치를 선택하세요', 1.8.x 버튼 **장치 선택**)에서 목록 맨 아래의 **No filtering**을 고릅니다. 이 문구는 영어로 표시됩니다. 이 선택은 운영체제 목록을 거르는 용도라서 직접 내려받은 이미지를 굽는 데는 영향이 없습니다. 2.x는 **다음**을 누릅니다.
4. 운영체제 선택 단계(2.x '운영 체제 선택', 1.8.x 버튼 **운영체제 선택**)에서 목록을 맨 아래로 내려 **사용자 정의 사용**(Use custom)을 고르고, 내려받은 `lekiwi1027.img.gz` 를 압축을 풀지 않은 그대로 선택합니다. 바로 위의 **삭제**(Erase)는 고르지 않습니다. 2.x는 **다음**을 누릅니다.
5. 저장소 선택 단계(2.x '저장 장치를 선택하세요', 1.8.x 버튼 **저장소 선택**)에서 **내 microSD 카드**를 고릅니다. 카드 용량이 맞는지 꼭 확인합니다. Imager는 10진수 단위로 보여 주므로 32GB 카드는 약 31.9GB로 보입니다. 다른 저장장치를 고르면 그 안의 데이터가 지워집니다. **시스템 드라이브 제외**(Exclude system drives)가 보이면 켜진 채로 둡니다. 2.x는 **다음**을 누릅니다.
6. 1.8.x만 해당합니다. **다음**(NEXT)을 누르면 OS 맞춤 설정을 적용할지 묻는데 **아니요**(NO)를 고릅니다. 맞춤 설정을 적용하면 Imager가 부팅 영역의 설정 파일(`user-data`)을 새로 써서 이미지에 들어 있는 계정 같은 설정이 바뀔 수 있기 때문입니다. 와이파이도 여기서 넣지 않습니다. 로봇의 와이파이는 첫 부팅 뒤 웹 화면에서 정합니다. 2.x는 직접 내려받은 이미지에 이 단계가 나오지 않으며, **사용자 지정을 건너뛰기**(Skip customisation) 버튼이 보이면 그것을 누릅니다.
7. 쓰기를 시작합니다.
   - **1.8.x (우분투 apt 버전)**: "모든 데이터가 지워집니다. 계속하시겠습니까?" 창에서 카드 이름이 맞는지 확인하고 **예**(YES)를 누릅니다.
   - **2.x (윈도우 설치 파일, 우분투 AppImage)**: 요약 화면에서 **기록**(Write)을 누릅니다. "You are about to ERASE all data on: …" 창에서 카드 이름이 맞는지 확인하고, 2초쯤 뒤에 눌러지는 **이해합니다. 삭제하고 기록**(I understand, erase and write)을 누릅니다.
8. 쓰기가 끝나면 이어서 검증(Verifying)이 자동으로 진행됩니다. 둘 다 끝날 때까지 기다리고, **검증 건너뛰기**(Skip verification)나 취소는 누르지 않습니다. 카드와 리더기 속도에 따라 합쳐서 수 분에서 십수 분 걸립니다.
9. **쓰기 완료**(Write complete) 화면이 나오면 굽기가 끝난 것입니다. 2.x는 저장 장치가 자동으로 꺼졌다고 알려 주고, 1.8.x는 **계속**(CONTINUE)을 누릅니다. 그다음 카드를 뽑습니다.

<!-- 그림 필요: Raspberry Pi Imager 운영체제 선택에서 '사용자 정의 사용'으로 lekiwi1027.img.gz 를 고른 화면 -->
<!-- 그림 필요: Raspberry Pi Imager 저장소 선택 화면 (microSD 카드 이름 · 용량 확인) -->

윈도우에서는 카드를 다시 꽂았을 때 포맷하라는 창이 뜰 수 있습니다.

> **경고** ⚠️ `WARN`
> <br>**포맷하라는 창이 뜨면 취소를 누르세요** "드라이브의 디스크를 포맷해야 합니다"(영어: You need to format the disk in drive X: before you can use it) 같은 안내가 나와도 **디스크 포맷**은 누르지 않습니다. 카드에는 윈도우가 읽는 첫 번째 영역(`system-boot`)과 리눅스 형식이라 읽지 못하는 두 번째 영역(`writable`)이 있어서, 읽지 못하는 쪽에만 이 안내가 나옵니다. 포맷하면 방금 구운 이미지가 지워집니다. 실수로 포맷했다면 4.2절을 처음부터 다시 진행합니다.

<!-- 그림 필요: 윈도우 '드라이브의 디스크를 포맷해야 합니다' 창과 취소 버튼 -->

### 4.3. (선택) 우분투에서 터미널로 굽기

GUI 없이 터미널만으로도 구울 수 있습니다. 우분투에서 카드 이름을 정확히 확인하는 데 자신이 있을 때만 사용합니다.

> **경고** ⚠️ `WARN`
> <br>`dd` 는 지정한 장치를 되돌릴 수 없게 덮어씁니다. 카드가 아닌 장치를 지정하면 **PC의 디스크가 지워질 수 있습니다.** 장치 이름을 `lsblk` 로 확인할 자신이 없다면 4.2절의 Raspberry Pi Imager를 사용합니다.

먼저 카드의 장치 이름을 찾습니다. **카드를 꽂기 전에 한 번, 꽂은 뒤에 한 번** 실행해서 새로 생긴 장치가 카드입니다.

```bash
# 우분투
lsblk -e7 -o NAME,SIZE,MODEL,TRAN,RM,MOUNTPOINTS
```

카드는 보통 `TRAN` 이 `usb`, `RM` 이 `1` 인 장치입니다. 크기는 카드 겉면보다 작게 보여서 32GB 카드는 약 `29.7G` 입니다. (`-e7` 은 snap이 만드는 `loop` 항목을 숨깁니다.) 노트북 내장 슬롯이라면 `mmcblk0` 으로 보입니다. 아래는 가상의 출력 예시입니다. `sda` 는 PC 안의 디스크이고 카드는 `sdb` 입니다.

```text
NAME     SIZE MODEL    TRAN RM MOUNTPOINTS
sda    476.9G SATA SSD sata  0
├─sda1   512M          sata  0 /boot/efi
└─sda2 476.4G          sata  0 /
sdb     29.7G SD/MMC   usb   1
├─sdb1   512M          usb   1 /media/…/system-boot
└─sdb2  29.2G          usb   1 /media/…/writable
```

SATA 디스크를 쓰는 PC에서는 `sda` 가 PC에 설치된 디스크이므로 카드로 착각하지 않습니다. `nvme0n1` 처럼 시스템이 설치된 장치도 절대 쓰지 않습니다.

확인한 이름을 `CARD=` 뒤에 적고(예: `/dev/sdb`), 마운트된 파티션을 해제한 뒤 압축을 풀면서 바로 카드에 기록합니다.

```bash
# 우분투
CARD=/dev/sdX    # sdX 를 카드 이름으로 바꿉니다 (예: /dev/sdb)
sudo umount "$CARD"?*
gunzip -c "$(xdg-user-dir DOWNLOAD)/lekiwi1027.img.gz" | sudo dd of="$CARD" bs=4M iflag=fullblock conv=fsync,nocreat status=progress
sync
```

`/dev/sdX` 를 바꾸지 않고 실행하면 `conv=nocreat` 때문에 '열기 실패' 오류만 나고 아무것도 쓰이지 않습니다. `umount` 가 '마운트되어 있지 않다'고 알려 주는 것은 괜찮습니다. 끝나면 마지막 줄에 `8644932096` 바이트를 복사했다고 나옵니다. 파일 관리자에서 카드의 꺼내기(⏏)를 눌러 안전하게 제거합니다.

> **팁** 💡`TIP`
> <br>진행 표시가 거의 100%가 된 뒤에도 `conv=fsync` 가 카드에 쓰기를 마무리하는 동안 멈춘 것처럼 보일 수 있습니다. 프롬프트가 돌아올 때까지 기다립니다. 압축 파일이 깨져 있으면 `unexpected end of file` 메시지가 나오고 카드가 중간까지만 쓰인 채 끝날 수 있으니, 3.2절의 해시 확인을 통과한 파일만 씁니다.

## 5. [로봇] 카드 꽂고 첫 부팅

### 5.1. 카드 꽂기

1. 로봇의 전원이 꺼져 있는지 확인합니다.
2. 라즈베리파이의 microSD 카드 슬롯에 카드를 끝까지 밀어 넣습니다. 기존에 꽂혀 있던 카드가 있다면 빼고 새 카드로 바꿉니다.
3. 로봇의 USB 케이블(카메라 두 대 · 라이다 · 모터 보드)이 라즈베리파이에 꽂혀 있는지 확인합니다. 카메라는 꽂은 자리에 따라 전방 · 손목이 정해지므로, 처음이라면 [카메라 연결](/docs/a-go/setup-cameraport)에서 자리를 확인합니다.
4. 전원을 켭니다. 랜선은 꽂지 않아도 됩니다.

<!-- 그림 필요: 라즈베리파이 4의 microSD 카드 슬롯에 카드를 꽂는 사진 (로봇에 달린 상태) -->

### 5.2. 첫 부팅

전원을 처음 켜면 **첫 부팅은 1~2분쯤** 걸립니다. 이 동안 라즈베리파이가 스스로 두 가지 일을 합니다.

- 줄여 두었던 저장 공간을 **카드 전체 크기로 늘립니다.**
- 이 카드만의 **SSH 호스트 키를 새로 만듭니다.** 그래서 같은 로봇이라도 카드를 다시 구우면 PC가 "다른 컴퓨터"로 봅니다 (7.2절).

이 작업은 처음 한 번만 합니다. 두 번째 부팅부터는 이 과정이 없습니다.

> **경고** ⚠️ `WARN`
> <br>**첫 부팅 중에는 전원을 끊지 마세요** 저장 공간을 늘리는 도중에 끊기면 카드가 손상될 수 있고, 그러면 4절부터 다시 구워야 합니다. 카드도 빼지 않습니다.

### 5.3. 첫 부팅이 끝나면 — AP 모드

새 카드에는 공유기 정보가 없으므로, 로봇이 스스로 와이파이를 띄웁니다. 이것을 **AP 모드**라고 합니다. 새로 구운 카드는 어느 로봇이든 같은 값으로 시작합니다.

| 항목 | 값 |
|---|---|
| 와이파이 이름 | `lekiwi01` (2.4GHz) |
| 비밀번호 | `lekiwi01` |
| 로봇 주소 | `192.168.4.1` |
| 웹 화면 | `http://192.168.4.1:8080` |

웹 화면은 로봇 전원을 켜면 저절로 뜹니다. 하지만 바퀴 · 팔 · 카메라를 쓰는 **로봇 기능**은 아직 꺼져 있습니다. 로봇 기능은 웹 화면이나 Physical Labs에서 **로봇 켜기**를 눌러야 켜지므로, 첫 부팅이 끝나도 로봇은 움직이지 않습니다.

<!-- 그림 필요: PC 또는 휴대폰의 와이파이 목록에 lekiwi01 이 보이는 화면 -->

> **성공** ✨ `SUCCESS`
> <br>**와이파이 목록에 `lekiwi01` 이 보이면 카드가 잘 구워진 것입니다** 다음 페이지 [처음 접속하기](/docs/a-go/first-connection)에서 이 와이파이에 붙어 웹 화면을 엽니다. 랜선으로 붙고 싶다면 [유선 연결](/docs/a-go/lekiwi-wired-connection)을 봅니다.

## 6. 새로 구운 카드에서 할 일

이미지에는 로봇마다 다른 값이 들어 있지 않습니다. 카드를 새로 구웠다면 아래 순서로 맞추면 편합니다. 로봇 번호를 먼저 정하는 까닭은, 공유기를 등록하기 전에 하는 것이 가장 간단하고 Physical Labs가 보정 이름에 로봇 이름을 쓰기 때문입니다.

| 순서 | 할 일 | 왜 필요한가 | 어디서 |
|---|---|---|---|
| 1 | **로봇 번호 정하기** (여러 대이거나 다시 구웠을 때) | 새로 구운 카드는 모두 이름 `lekiwi01` · 번호 1번입니다. 같은 곳에 여러 대를 두면 서로 구분되지 않습니다 | [처음 접속하기](/docs/a-go/first-connection) |
| 2 | **AP 이름 · 비밀번호 바꾸기** (권장) | 새로 구운 카드는 모든 로봇이 `lekiwi01` / `lekiwi01` 입니다. 로봇이 여러 대면 휴대폰 · 노트북이 다른 로봇에 붙을 수 있고, AP 비밀번호를 아는 사람은 누구나 웹 화면으로 로봇을 조작할 수 있습니다 | [네트워크 (AP · 공유기)](/docs/a-go/lekiwi-wifi-static-ip) |
| 3 | **공유기에 연결** (선택) | AP 모드에는 인터넷이 없습니다. 노트북이 인터넷과 로봇을 함께 쓰려면 로봇을 공유기에 붙입니다 | [네트워크 (AP · 공유기)](/docs/a-go/lekiwi-wifi-static-ip) |
| 4 | **ROS_DOMAIN_ID 바꾸기** (같은 공유기에 여러 대일 때) | 모든 카드가 같은 값으로 시작합니다. 같은 공유기에서 값이 같으면 로봇끼리 ROS 토픽이 섞입니다. 지금 값은 웹 화면 대시보드의 **로봇** 칸 `ROS` 줄에 보입니다 | [문제 해결](/docs/a-go/troubleshooting) · [저장소와 구조](/docs/a-go/developer) |
| 5 | **팔로워 팔 보정 → 접은 자세 저장** | 이미지에는 보정과 접은 자세가 없습니다. 보정이 없으면 Physical Labs의 텔레오퍼레이션 · 데이터 수집에 관측이 오지 않습니다. 접은 자세가 없으면 팔에 힘이 들어간 채 로봇을 끌 때 팔을 접지 못해 끄기가 멈춥니다. 같은 팔에 카드만 다시 구웠다면 웹 화면의 **모터 값으로 파일 만들기** 로 보정 파일을 되살릴 수 있습니다 | [캘리브레이션](/docs/a-go/start-calibration) |

> **팁** 💡`TIP`
> <br>카드를 여러 장 새로 구웠다면 로봇을 **한 대씩** 켜서 이름 · 번호 · AP 이름을 정합니다. 모두 같은 와이파이 이름 `lekiwi01` 로 뜨기 때문에, 한꺼번에 켜면 지금 어느 로봇에 붙었는지 알기 어렵습니다.

## 7. 카드를 다시 구울 때

카드가 손상됐거나 처음 상태로 되돌리고 싶을 때도 같은 방법으로 다시 굽습니다. 다시 구우면 카드는 이미지 그대로의 처음 상태가 됩니다.

### 7.1. 굽기 전에 옮겨 둘 것

카드에만 있던 것은 다시 구우면 사라집니다. 필요한 것은 먼저 PC로 옮기고, 다시 정할 값은 적어 둡니다.

| 무엇 | 로봇 안 위치 · 확인하는 곳 |
|---|---|
| 팔로워 팔 보정 파일 | `~/.cache/huggingface/lerobot/calibration/robots/lekiwi/` |
| 지도 (웹 화면 지도 작성으로 만든 것) | `~/maps/lekiwi/` |
| 직접 만들거나 고친 파일 | 만든 곳 |
| 다시 정할 값 | 웹 화면 대시보드 **로봇** 칸의 `호스트`(로봇 이름)와 `ROS` 줄의 도메인 번호를 적어 둡니다. AP 이름 · 비밀번호와 공유기는 6절대로 다시 정합니다 |

PC에서 아래처럼 보정 파일과 지도를 받아 둡니다. 아래 명령의 `192.168.4.1` 은 AP에 붙어 있을 때의 로봇 주소입니다. 공유기에 붙어 있다면 `lekiwi01.local` 이나 로봇 IP로 바꿉니다. 비밀번호는 스페이스 한 번입니다. 지도를 만든 적이 없다면 두 번째 명령은 '없다'고 나오는데, 옮길 것이 없다는 뜻입니다.

```bash
# 우분투
mkdir -p ~/lekiwi-backup
scp -r roboseasy@192.168.4.1:/home/roboseasy/.cache/huggingface/lerobot/calibration/robots/lekiwi ~/lekiwi-backup/calibration
scp -r roboseasy@192.168.4.1:/home/roboseasy/maps/lekiwi ~/lekiwi-backup/maps
```

```bat
:: 윈도우
mkdir "%USERPROFILE%\lekiwi-backup"
scp -r roboseasy@192.168.4.1:/home/roboseasy/.cache/huggingface/lerobot/calibration/robots/lekiwi "%USERPROFILE%\lekiwi-backup\calibration"
scp -r roboseasy@192.168.4.1:/home/roboseasy/maps/lekiwi "%USERPROFILE%\lekiwi-backup\maps"
```

PC에 있는 것은 카드와 상관없이 남습니다. 리더암 보정, Physical Labs의 로봇 설정과 데이터셋은 다시 구워도 그대로입니다.

### 7.2. SSH 호스트 키 경고

다시 구운 카드는 첫 부팅 때 SSH 호스트 키를 새로 만듭니다 (5.2절). 그래서 PC가 예전에 이 로봇에 SSH로 접속한 적이 있다면, 다음 접속 때 PC는 "다른 컴퓨터가 같은 주소에 있다"고 보고 경고를 띄웁니다. 카드를 새로 구웠다면 정상입니다.

#### 터미널 (우분투 · 윈도우)

`ssh` 가 아래 경고를 띄우고 접속하지 않습니다 (마지막 줄 `Host key verification failed.`).

```text
@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
@    WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED!     @
@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
```

PC가 기억하던 예전 키를 지웁니다. 우분투 터미널과 윈도우 명령 프롬프트 모두 같은 명령이며, 접속에 썼던 주소마다 한 번씩 실행합니다.

```bash
ssh-keygen -R 192.168.4.1
ssh-keygen -R lekiwi01.local
```

다시 `ssh roboseasy@192.168.4.1` 로 접속하면 처음 접속할 때처럼 `yes/no` 를 묻습니다. `yes` 를 입력하고, 비밀번호는 스페이스 한 번입니다.

#### Physical Labs

Physical Labs가 SSH를 쓰는 기능(예: **📶 와이파이 설정…**)을 누르면 **호스트 키가 바뀌었습니다** 창이 뜹니다. 카드를 새로 구웠다면 **Yes** 를 누릅니다. `다시 시도해 주세요` 가 나오면 하던 버튼을 한 번 더 누릅니다. 앱은 자기 전용 목록만 지우므로, 터미널의 경고는 위 명령으로 따로 정리합니다. 이어서 **로봇 비밀번호** 창이 뜹니다. 다시 구운 카드에는 앱이 예전에 등록해 둔 키가 없기 때문입니다. 입력칸에는 기본 비밀번호(스페이스 한 번)가 이미 들어 있으므로, 비밀번호를 바꾸지 않았다면 아무것도 입력하지 않고 **OK** 를 누릅니다. 스페이스를 한 번 더 넣으면 비밀번호가 틀립니다.

> **경고** ⚠️ `WARN`
> <br>**카드를 다시 구운 적이 없는데 이 경고가 뜬다면** 다른 기기에 접속하고 있을 수 있습니다. 키를 지우기 전에 PC가 맞는 네트워크에 붙어 있는지, 로봇 주소가 맞는지 먼저 확인합니다.

### 7.3. 로봇 번호 되돌리기

다시 구운 카드는 이름이 `lekiwi01`, 번호가 1번으로 돌아갑니다. 원래 다른 번호(예: `lekiwi03`)였다면, 7.1절에서 적어 둔 `호스트` 의 번호로 되돌립니다. 로봇에 SSH로 접속해 `sudo ~/lekiwi_net/clone_init.sh lekiwiNN N` 을 실행하고 재부팅하는 방법은 [처음 접속하기](/docs/a-go/first-connection)의 **로봇 번호 정하기** 절에 있습니다. 카드를 구운 직후, 공유기를 등록하기 전에 하는 것이 가장 간단합니다.

되돌리기 전까지 로봇 이름 주소는 `lekiwi01.local` 입니다. 브라우저 · Physical Labs에 예전 이름 주소(`lekiwi03.local`)를 적어 두었다면, 번호를 되돌리고 재부팅한 뒤에 다시 닿습니다. 이 명령은 AP 이름 · 비밀번호와 ROS_DOMAIN_ID를 바꾸지 않습니다. AP 이름 · 비밀번호는 [네트워크 (AP · 공유기)](/docs/a-go/lekiwi-wifi-static-ip)에서, ROS_DOMAIN_ID는 [저장소와 구조](/docs/a-go/developer)를 보고 따로 맞춥니다.

## 8. 문제 해결

| 증상 | 확인할 것 |
|---|---|
| 드라이브에서 "현재 이 파일을 보거나 다운로드할 수 없습니다"(영어: Sorry, you can't view or download this file at this time)가 뜬다 | 최근에 너무 많은 사람이 이 파일을 받아서 Google이 일시적으로 막은 것입니다. 풀리기까지 **최대 24시간** 걸릴 수 있습니다. 급하면 Google 계정으로 로그인해 파일의 **사본 만들기**(⋮ 메뉴 또는 마우스 오른쪽 버튼)로 **내 드라이브에 복사**한 뒤, 내 드라이브에 생긴 사본을 내려받습니다. 내 드라이브에 3GB 이상 빈 공간이 필요하고, 다 받은 뒤에는 사본을 지워도 됩니다. |
| 내려받은 파일의 해시가 다르다 | 다운로드가 끊기거나 일부가 깨진 것입니다. 파일을 지우고 다시 받습니다. 두 번 받아도 계속 다르면 이 문서의 값이 오래된 것일 수 있으니 굽지 말고 RoboSEasy에 문의합니다. |
| Imager 파일 선택 창에 `lekiwi1027.img.gz` 가 보이지 않는다 | 기본 필터에 `.gz` 가 들어 있어 보통은 바로 보입니다. 선택 창이 열린 폴더(보통 다운로드)에 파일이 있는지 확인하고, 파일 이름이 `.crdownload` 나 `.part` 로 끝나면 다운로드가 아직 끝나지 않은 것이니 기다립니다. 그래도 안 보이면 파일 형식을 **All files**(모든 파일)로 바꿉니다. |
| 쓰기 또는 검증 중 오류가 나거나 카드가 '읽기 전용'(1.8.x는 '쓰기 금지된 SD card')으로 표시된다 | microSD 카드를 SD 어댑터에 끼워 쓴다면 어댑터 옆면의 잠금(LOCK) 스위치를 풀림 쪽으로 밉니다. 그다음 카드 리더기나 USB 포트를 바꿔 다시 시도합니다. 같은 카드에서 계속 실패하면 카드 불량일 수 있으니 다른 카드를 씁니다. |
| 쓰는 도중 `Error writing…`(쓰기 오류)나 용량 부족 오류가 난다 | 압축을 풀면 8,644,932,096바이트(약 8.6GB)라서 8GB 카드에는 들어가지 않습니다. `.img.gz` 는 압축을 푼 크기를 Imager가 미리 알 수 없어 쓰기 전에 걸러 주지 못하고, 카드가 가득 차는 순간 쓰기 오류로 나타납니다. 16GB 이상 카드를 씁니다. |
| 굽고 나서 윈도우가 포맷하라고 한다 | **취소**를 누릅니다 (4.2절 경고 참고). |
| 전원을 켜도 라즈베리파이가 부팅하지 않는다 | 배터리 스위치가 켜져 있는지, 배터리가 충분히 충전되어 있는지, 카드가 슬롯에 끝까지 들어갔는지 확인합니다. 그래도 안 되면 카드를 다시 굽습니다. |
| 5분이 지나도 와이파이 목록에 `lekiwi01` 이 보이지 않는다 | 로봇의 와이파이는 2.4GHz입니다. 노트북 · 휴대폰의 와이파이가 켜져 있는지, 로봇 가까이에 있는지 확인합니다. 그래도 안 보이면 [유선 연결](/docs/a-go/lekiwi-wired-connection)로 랜선 접속을 시도해 로봇이 부팅됐는지 봅니다. 카드를 다시 굽는 것은 마지막에 시도합니다. |
| 와이파이 목록에 `lekiwi01` 이 여러 개 보인다 | 새로 구운 카드는 모두 같은 이름으로 뜹니다. 로봇을 한 대만 켜고 AP 이름을 바꾼 뒤 다음 로봇을 켭니다 (6절 팁). |
| SSH 접속이 `REMOTE HOST IDENTIFICATION HAS CHANGED` 로 막힌다 | 카드를 다시 구워 호스트 키가 바뀐 것입니다. `ssh-keygen -R <로봇 주소>` 로 예전 키를 지웁니다 (7.2절). |
| 웹 화면은 열리는데 바퀴 · 팔이 움직이지 않는다 | 정상입니다. 로봇 기능이 꺼진 채 시작합니다. [대시보드와 조작 권한](/docs/a-go/web-dashboard)에서 로봇을 켜고, 팔은 [캘리브레이션](/docs/a-go/start-calibration)을 먼저 합니다. |

## 9. 정리

- 라즈베리파이는 **microSD 카드**로 부팅하므로, A-Go(LeKiwi)를 쓰려면 이미지를 구운 카드가 필요합니다.
- 새 이미지 `lekiwi1027` 에는 Ubuntu 24.04.4, ROS 2 Jazzy, 웹 화면, 네트워크 도구가 들어 있어 따로 설치할 것이 없습니다. 카드는 **16GB 이상**을 씁니다.
- 이미지는 `.img.gz` 그대로 **Raspberry Pi Imager**의 **사용자 정의 사용**(Use custom)으로 굽고, 내려받은 뒤 **SHA-256**으로 파일을 확인할 수 있습니다.
- 첫 부팅(1~2분)에는 저장 공간을 늘리고 SSH 호스트 키를 만들므로 전원을 끊지 않습니다. 끝나면 로봇이 **AP 모드**로 와이파이 `lekiwi01` 을 띄웁니다.
- 새로 구운 카드에는 보정 · 접은 자세 · 공유기 정보가 없습니다. 다시 구우면 이름 · 번호 · AP 이름도 처음 값으로 돌아가고, SSH 호스트 키 경고가 뜹니다.

카드가 준비되었습니다. 다음 페이지에서 로봇이 띄운 와이파이에 붙어 웹 화면을 엽니다.
