# 로봇 설정

Physical Labs 에서 로봇 팔을 쓰려면 먼저 **로봇**을 하나 등록합니다. 로봇에는 이름, 팔로워 · 리더 팔이 꽂힌 USB 포트, 카메라가 담기고, 칼리브레이션 · 텔레오퍼레이션 · 데이터 수집 같은 다른 탭은 모두 여기서 저장한 값을 씁니다. 이 페이지에서는 SO-101(A-Ba)을 예로 새 로봇을 만들고, 포트와 카메라를 정해 저장하는 방법을 안내합니다. Ubuntu 에서는 저장할 때 USB 포트도 함께 고정되어, 케이블을 다시 꽂아도 같은 팔이 같은 이름으로 잡힙니다.

> 🎯 **학습 목표**
>
> - 로봇 창고에서 새 로봇을 만들고, robot id · teleop id 를 알맞게 지을 수 있다.
> - 팔로워 · 리더 팔의 USB 포트와 카메라를 고르고, 미리보기로 확인할 수 있다.
> - **로봇 저장** 이 USB 포트를 어떻게 고정하는지, 관리자 비밀번호를 왜 묻는지 설명할 수 있다.
> - 저장한 로봇의 포트 · 카메라를 고치거나 로봇을 지울 수 있다.
> - `시리얼 포트 권한 문제` 창이 뜨면 스스로 해결할 수 있다.

## 1. 시작하기 전에

### 1.1. 로봇 하나 = 팔 두 대 + 카메라

SO-101 로봇 하나는 팔 두 대로 이루어집니다. 두 팔에는 각각 모터 보드가 있고, 보드마다 USB 케이블로 PC 에 꽂습니다. 그래서 PC 에는 시리얼 포트가 두 개(`/dev/ttyACM0`, `/dev/ttyACM1` 처럼) 보입니다.

| 장치 | 앱에서 쓰는 이름 | 하는 일 |
|---|---|---|
| 팔로워(follower) 팔 | **follower arm** — 이름은 **robot id** | 실제로 일을 하는 팔입니다. 리더 · 학습한 모델이 이 팔을 움직입니다 |
| 리더(leader) 팔 | **leader arm** — 이름은 **teleop id** | 사람이 손으로 잡고 움직이는 팔입니다. 팔로워가 이 팔을 따라 합니다 |
| 카메라 (선택) | **2. Camera** 칸 | 데이터 수집 · 추론에 쓰는 USB 카메라입니다. 여러 대를 달 수 있습니다 |

### 1.2. 준비물

| 준비물 | 설명 |
|---|---|
| 팔로워 · 리더 팔 | 조립을 마친 SO-101 두 대. 조립은 [A-Ba(SO-ARM101) 문서](/docs/a-ba)를 따릅니다 |
| 모터 전원 · USB 케이블 | 두 팔의 보드에 전원을 넣고 USB 로 PC 에 꽂습니다. **로봇 저장 을 누를 때 두 팔이 모두 꽂혀 있어야 합니다** |
| 카메라 (선택) | USB 카메라. 나중에 추가해도 됩니다 |
| 관리자 비밀번호 | Ubuntu 에서 **로봇 저장** 을 누를 때 묻습니다 (sudo 에 쓰는 로그인 비밀번호) |
| Physical Labs | Ubuntu(.deb) 0.1.9 기준입니다. 설치는 [설치와 첫 실행](/docs/physical-labs/install) |

로봇 설정 탭은 앱의 기본 구성만으로 열립니다. 따로 설치할 기능 패키지는 없습니다.

> **정보** ℹ️ `INFO`
> <br>**모터 ID 셋업도 이 탭 안에서 할 수 있습니다** 새 모터로 팔을 조립한다면 모터마다 번호(ID)를 붙여야 합니다. 로봇 설정 탭 맨 아래 **모터** 칸에 ID 셋업 마법사가 들어 있습니다 (3.4절, 자세한 순서는 [모터 셋업](/docs/physical-labs/motor-setup)).

### 1.3. 이 페이지에서 쓰는 예시 값

| 항목 | 예시 값 |
|---|---|
| 기종 | `SO-101` |
| robot id (팔로워 이름) | `my_so101` |
| teleop id (리더 이름) | `my_so101_leader` |
| 팔로워 · 리더 포트 | `/dev/ttyACM0` · `/dev/ttyACM1` (PC 마다, 꽂는 순서마다 다릅니다) |
| 카메라 이름 | `front` (앞에서 보는 카메라) · `wrist` (손목 카메라) |

## 2. [앱] 새 로봇 만들기

### 2.1. 로봇 창고 열기

왼쪽 사이드바에서 **로봇 창고** 를 누릅니다. 페이지 제목은 **로봇** 이고, 저장한 로봇이 카드로 보입니다. 카드의 굵은 글자는 robot id, 아래 작은 글자는 기종입니다. 아직 로봇이 없으면 `아직 등록된 로봇이 없습니다.` 라고 나옵니다.

![로봇 창고 — 오른쪽 위에 로봇 추가 · 로봇 삭제 버튼, 아래에 저장한 로봇 카드](/img/physical_labs/robots.webp)

*로봇 창고. 카드 하나가 로봇 하나입니다 (그림의 카드는 LeKiwi 로봇 `lekiwi01`).*

### 2.2. 기종 고르기

오른쪽 위 **+ 로봇 추가** 를 누르면 `새 로봇 생성` 창이 뜹니다. 쓸 기종의 카드를 누릅니다.

![새 로봇 생성 창 — SO-101 · SO-102 · Lekiwi 카드와 흐리게 보이는 reBot · Dual SO-101 · Dual SO-102](/img/physical_labs/new-robot-dialog.webp)

*`사용할 로봇 기종을 선택하세요.` — `준비 중` 배지가 붙은 흐린 카드는 아직 고를 수 없습니다.*

| 카드 | 화면 설명 | 이 문서에서 |
|---|---|---|
| **SO-101** | `Feetech 6 DoF 로봇 팔` | A-Ba(SO-ARM101). 팔로워 · 리더 모두 PC 에 USB 로 꽂고, 팔마다 모터 6개 |
| **SO-102** | `로보시지 자체 개발 7 DoF 로봇 팔` | 손목 관절이 하나 더 있는 7축 팔 (7.1절) |
| **Lekiwi** | `모바일 베이스 + 로봇 팔` | A-Go(LeKiwi). 칸 구성이 다릅니다 (7.2절) |
| reBot · Dual SO-101 · Dual SO-102 | `준비 중` | 아직 고를 수 없습니다 |

### 2.3. 저장하기 전에는 '임시 로봇'

카드를 누르면 그 기종의 빈 로봇이 **로봇 설정** 탭으로 열립니다. 화면 맨 위 제목은 아직 기종 이름(`SO-101`)이고, **로봇 저장** 을 누르기 전까지는 로봇 창고에 카드가 생기지 않습니다. 저장하면 제목이 robot id 로 바뀌고 카드가 생깁니다.

> **경고** ⚠️ `WARN`
> <br>**다른 탭으로 가기 전에 로봇 저장 부터** 저장하기 전에는 칼리브레이션 · 텔레오퍼레이션 같은 다른 탭이 이 로봇의 포트와 이름을 모릅니다. 칸을 채웠으면 먼저 **로봇 저장** 을 누르세요. 저장하지 않고 다른 곳으로 가면 입력한 내용은 로봇 창고에 남지 않습니다.

## 3. [앱] 로봇 설정 탭의 칸

![SO-101 로봇의 로봇 설정 탭 — 이름(robot id · teleop id), 포트 › 1. USB(follower arm · leader arm), 2. Camera](/img/physical_labs/robot-settings.webp)

*로봇 설정 탭 윗부분 (저장한 로봇 `a-ba`). 그림의 포트 `ttyPLDOC0  (연결 안 됨)` 은 촬영용 값이고, 실제로는 `/dev/ttyACM0` 처럼 보입니다. 저장한 뒤에는 오른쪽 이름 칸에 robot id · teleop id 가 채워져 보입니다.*

위에서부터 이런 칸이 있습니다.

| 칸 | 들어 있는 것 | 꼭 채워야 하나 |
|---|---|---|
| 맨 위 | 동그란 로봇 그림, **로봇 저장** · **로봇 삭제** | — |
| **이름** | **robot id:** · **teleop id:** | 둘 다 채웁니다 |
| **포트** › **1. USB** | **새로고침**, **follower arm:** · **leader arm:** 의 포트 목록과 오른쪽 이름 칸 | 포트 두 개는 채우고, 이름 칸은 비워 둡니다 |
| **2. Camera** | **새로고침**, 카메라 줄, **+ camera** | 선택 |
| **모터** | ID 셋업 마법사 | 모터 ID 를 붙여야 할 때만 |

### 3.1. 이름 — robot id · teleop id

- **robot id** 는 팔로워 팔(= 이 로봇)의 이름입니다. 로봇 창고 카드의 제목, 팔로워 보정 파일의 이름(`my_so101.json`), 팔로워 포트의 고정 이름(`/dev/my_so101`)이 됩니다.
- **teleop id** 는 리더 팔의 이름입니다. 리더 보정 파일의 이름과 리더 포트의 고정 이름(`/dev/my_so101_leader`)이 됩니다.

칸이 비어 있을 때 보이는 회색 글자(`예: my_so101`, `예: my_so101_leader`)가 앱이 권하는 이름 모양입니다.

| 규칙 | 설명 |
|---|---|
| 쓸 수 있는 글자 | 영문 · 숫자 · `_` · `-` · `.` 만 씁니다. 한글 · 띄어쓰기는 안 됩니다 (첫 글자는 영문 · 숫자 · `_`, 64자 이하) |
| 로봇마다 다르게 | robot id 는 로봇마다 달라야 합니다. 이미 있는 robot id 로는 저장되지 않고 (`이미 같은 robot id 가 있습니다`), 그 과정에서 원래 로봇의 포트 고정 규칙 파일이 지워집니다 (8절). 이름을 짓기 전에 로봇 창고의 이름을 확인하세요 |
| 처음 정한 뒤 바꾸지 않기 | 보정 파일이 이 이름으로 저장됩니다. 나중에 이름을 바꾸면 새 이름의 보정 파일이 없어 칼리브레이션을 다시 해야 합니다 |

> **팁** 💡`TIP`
> <br>**로봇을 여러 대 등록한다면 teleop id 와 카메라 이름도 로봇마다 다르게** 이 이름들은 PC 전체에서 쓰는 장치 이름(`/dev/<이름>`)이 됩니다. 두 로봇이 모두 `leader` 나 `front` 처럼 같은 이름을 쓰면 장치 이름이 겹쳐 엉킬 수 있으니, `a_leader` · `b_leader` 처럼 구분해 짓습니다.

### 3.2. 포트 › 1. USB

1. **[PC]** 두 팔의 보드에 전원을 넣고 USB 를 PC 에 꽂습니다.
2. **[앱]** **1. USB** 의 **새로고침** 을 누릅니다.
3. **[앱]** **follower arm:** 목록에서 팔로워 보드의 포트를, **leader arm:** 목록에서 리더 보드의 포트를 고릅니다.
4. **[앱]** 오른쪽 이름 칸은 **비워 둡니다.** 비워 두면 회색으로 보이는 robot id · teleop id 가 그대로 고정 이름이 됩니다. (robot id 칸이 비어 있으면 회색 글자가 `robot id 를 먼저 저장하세요` 로 보입니다 — 위 **이름** 칸부터 채우라는 뜻입니다.)

포트 목록에는 이런 항목이 보입니다.

| 목록의 항목 | 뜻 |
|---|---|
| `— 포트 선택 —` | 아직 고르지 않았습니다 |
| `/dev/ttyACM0` · `/dev/ttyACM1` | 지금 꽂혀 있는 USB 시리얼 포트입니다. 번호는 꽂는 순서에 따라 바뀝니다 |
| `/dev/…-follower` · `/dev/…-leader` | `-follower` · `-leader` 로 끝나는 고정 이름입니다. 다른 로봇의 것은 숨겨지고, `/dev/my_so101` 처럼 다르게 끝나는 고정 이름은 이 목록에 나오지 않습니다 (다른 탭에서는 그대로 쓰입니다) |
| `ttyACM0  (연결 안 됨)` | 저장해 둔 포트가 지금은 안 보입니다. 케이블 · 전원을 확인하고 **새로고침** 을 누릅니다 |

> **팁** 💡`TIP`
> <br>**어느 포트가 어느 팔인지 모르겠다면** 리더 팔의 USB 만 잠깐 뽑고 **새로고침** 을 누르세요. 목록에 남은 `/dev/ttyACM*` 가 팔로워입니다. 리더를 다시 꽂고 **새로고침** 을 한 번 더 누른 뒤, 새로 생긴 포트를 리더로 고릅니다.

> **경고** ⚠️ `WARN`
> <br>**이름 칸에 robot id 와 다른 이름을 적지 마세요** 엔드이펙터 탭은 팔로워의 고정 이름(`/dev/<이름>`)으로 보정 파일을 찾습니다. 이름 칸에 robot id 와 다른 이름을 적으면 엔드이펙터가 보정 파일을 찾지 못해 연결하지 못합니다.

### 3.3. 2. Camera

1. **[PC]** 카메라를 USB 에 꽂습니다.
2. **[앱]** **+ camera** 를 누릅니다. 카메라 줄이 하나 생깁니다.
3. **[앱]** 왼쪽 목록(`— 카메라 선택 —`)에서 장치를 고릅니다. `/dev/video0` · `/dev/video2` 처럼 짝수 번호만 보입니다 (홀수 번호는 영상이 아닌 보조 장치라 앱이 감춥니다).
4. **[앱]** 가운데 이름 칸에 이름을 씁니다 (예: `front`).
5. **[앱]** **▶** 를 눌러 고른 카메라가 맞는지 영상으로 확인합니다. 영상이 나오는 동안 버튼은 **■** 로 바뀌고, 다시 누르면 멈춥니다.
6. 카메라 수만큼 되풀이합니다. 쓰지 않을 줄은 **✕** 로 지웁니다.

<!-- 그림 필요: 2. Camera 에 카메라 줄 2개(front · wrist)를 넣고 한 줄을 ▶ 로 미리보기 켠 상태 (SO-101) -->

| 카메라 줄의 칸 | 설명 |
|---|---|
| 장치 목록 | `/dev/video2` 처럼 보입니다. PC 에 `v4l2-ctl`(`v4l-utils` 패키지)이 있으면 `/dev/video2  —  <카메라 모델 이름>` 처럼 모델 이름도 함께 보여 노트북 내장 카메라와 구별하기 쉽습니다 |
| 이름 칸 (`예: cam_top`) | 카메라 이름입니다. 데이터셋에 `observation.images.<이름>` 으로 들어갑니다 |
| **▶** / **■** | 미리보기 켜기 / 끄기 (`선택한 카메라 라이브 미리보기`). 미리보기 칸은 `연결 중…` 다음에 영상이 나옵니다 |
| **✕** | 이 카메라 줄을 지웁니다 |

카메라 이름은 이렇게 짓습니다.

- **역할 단어를 넣습니다.** 앞 · 위에서 작업대를 보는 카메라는 `front` · `top`, 손목 카메라는 `wrist` 처럼 짓습니다. SmolVLA 처럼 미리 학습된 모델을 파인튜닝할 때 앱이 이름 속 단어로 카메라 자리를 짝짓습니다 ([훈련](/docs/physical-labs/training)).
- 이름 규칙은 robot id 와 같습니다 (영문 · 숫자 · `_` · `-` · `.`). 카메라 줄을 만들었으면 이름을 꼭 채워야 저장됩니다.
- `cam_` 으로 시작하는 이름(`cam_front`)을 쓰면 저장한 뒤 장치 목록에 고정 이름(`cam_front  →  video2`)으로 보이고, 다음에 로봇을 열 때 카메라 줄이 `/dev/video2  (연결 안 됨)` 으로 보일 수 있습니다 (8절). 표시만 그렇고, 어느 이름이든 동작에는 문제가 없습니다.

> **정보** ℹ️ `INFO`
> <br>**해상도와 FPS 는 고르지 않습니다** 앱은 카메라가 처음 열릴 때 내주는 기본값을 읽어 저장하고, 텔레오퍼레이션 · 데이터 수집은 그 값을 그대로 씁니다. **2. Camera** 의 **새로고침** 을 누르면 카메라를 하나씩 잠깐 열어 읽은 값을 목록에 `· 640x480@30fps` 처럼 붙여 보여 줍니다. 카메라 한 대에 0.3~2초쯤 화면이 멈출 수 있고, 켜 둔 미리보기는 멈춥니다. 새로고침 없이 저장해도 저장 직전에 값을 읽습니다. 데이터 수집의 FPS 는 이 값보다 크게 잡지 마세요 ([데이터 수집](/docs/physical-labs/data-record)).

### 3.4. 모터 — ID 셋업 마법사

![로봇 설정 탭 아래 모터 칸 — 포트 · 새로고침 · 연결, Step 1/6: ID 1 할당 안내, ID 1~6 단계 목록](/img/physical_labs/robot-settings-motor.webp)

*모터 칸에는 ID 셋업 마법사가 들어 있습니다 (SO-101 은 6단계, SO-102 는 7단계).*

새 모터로 팔을 조립하거나 모터를 바꿨다면 이 칸에서 모터마다 ID 를 붙입니다. 모터를 **한 대씩** 연결해 ID 1 부터 차례로 할당하고, 할당한 모터는 가운데 위치(2048)로 실제로 움직입니다. 순서와 주의할 점은 [모터 셋업](/docs/physical-labs/motor-setup)에 자세히 있습니다. 이미 ID 셋업을 마친 팔이라면 이 칸은 건너뜁니다.

- **포트:** 가 셋업할 팔의 포트인지 먼저 확인합니다. 저장한 로봇이면 팔로워 포트가 미리 골라져 있으니, 리더 팔의 모터를 셋업할 때는 포트를 바꿔 고르세요.
- 셋업을 마치면 **연결 해제** 를 누릅니다. 이 칸의 연결은 다른 탭으로 옮겨도 끊기지 않아, 그대로 두면 칼리브레이션 같은 다른 탭과 같은 포트를 함께 쓰게 됩니다.

## 4. [앱] 로봇 저장 — USB 포트 고정과 함께

### 4.1. 로봇 저장 이 켜지는 조건

**로봇 저장** 은 robot id · teleop id · **follower arm** 포트 · **leader arm** 포트, 네 가지가 모두 채워지면 켜집니다. 이름 칸과 카메라는 비어 있어도 됩니다.

### 4.2. 저장 순서

1. **[앱]** **로봇 저장** 을 누릅니다.
2. **[앱]** 앱이 입력을 검사하고, 두 팔 보드의 **USB 시리얼 번호**(보드마다 다른 고유 번호)를 읽습니다. 이때 두 팔이 꽂혀 있어야 합니다.
3. **[앱]** `로봇 저장 — 미리보기` 창이 뜹니다. `다음 udev 룰을 시스템에 적용합니다.` · `대상 파일: /etc/udev/rules.d/99-my_so101.rules` · `적용 시 관리자 비밀번호 입력창이 1 회 나타납니다.` 아래에 적용할 규칙이 보입니다. **적용** 을 누릅니다.
4. **[PC]** 관리자 비밀번호 입력 창에 로그인 비밀번호를 넣습니다.
5. **[앱]** `로봇이 저장되었습니다.` 창이 뜹니다. 맨 위 제목이 robot id 로 바뀌고, 로봇 창고에 카드가 생깁니다.
6. **[PC]** 창의 안내(`최초 저장 후 USB 케이블을 한 번 재연결하면 심볼릭 링크가 생성됩니다.`)대로 **두 팔의 USB 케이블을 한 번 뽑았다가 다시 꽂습니다.**

![로봇 저장 — 미리보기 창 — 다음 udev 룰을 시스템에 적용합니다, 대상 파일 /etc/udev/rules.d/99-a-ba.rules, 규칙 원문, 적용 · 취소 버튼](/img/physical_labs/udev-rules-preview-dialog.webp)

*`로봇 저장 — 미리보기` 창. 그림은 robot id `a-ba` · teleop id `leader` 로 카메라 없이 저장할 때입니다.*

카메라까지 넣었다면 규칙은 이런 모양입니다. 괄호 부분에는 실제 보드 번호가, `KERNELS` 에는 카메라를 꽂은 USB 구멍의 위치가 들어갑니다.

```text
# PhysicalLabs - auto-generated. Do not edit manually.
# Regenerate via '로봇 설정 > 포트 고정하기' buttons.

# BEGIN PhysicalLabs USB serial rules
SUBSYSTEM=="tty", ATTRS{serial}=="(팔로워 보드 번호)", SYMLINK+="my_so101"
SUBSYSTEM=="tty", ATTRS{serial}=="(리더 보드 번호)", SYMLINK+="my_so101_leader"
# END PhysicalLabs USB serial rules

# BEGIN PhysicalLabs camera rules
SUBSYSTEM=="video4linux", KERNELS=="1-1:1.0", ATTR{index}=="0", SYMLINK+="front"
SUBSYSTEM=="video4linux", KERNELS=="1-2:1.0", ATTR{index}=="0", SYMLINK+="wrist"
# END PhysicalLabs camera rules
```

> **경고** ⚠️ `WARN`
> <br>**취소하면 아무것도 저장되지 않습니다** 미리보기 창에서 **취소** 를 누르면 `rules 작성이 취소되었습니다. 저장되지 않았습니다.`, 비밀번호 창을 닫거나 비밀번호가 틀리면 `rules 작성이 실패했습니다. 저장되지 않았습니다.` 가 뜨고 이름 · 포트 · 카메라 모두 저장되지 않습니다. Ubuntu 에서는 포트 고정까지 끝나야 로봇이 저장됩니다. 다시 **로봇 저장** 을 눌러 **적용** 하세요.

### 4.3. 포트 고정이란?

USB 장치의 이름(`/dev/ttyACM0`, `/dev/video2`)은 꽂는 순서에 따라 바뀝니다. 그대로 두면 다음에 팔로워 · 리더가 뒤바뀌어 엉뚱한 팔에 명령이 갈 수 있습니다. **로봇 저장** 은 Ubuntu 의 udev 규칙으로 장치마다 바뀌지 않는 이름(`/dev/<이름>`)을 붙여 둡니다.

| 대상 | 무엇으로 알아보나 | 생기는 이름 (예) | 알아 둘 것 |
|---|---|---|---|
| 팔로워 · 리더 팔 | 보드의 USB 시리얼 번호 | `/dev/my_so101` · `/dev/my_so101_leader` | 어느 USB 구멍에 꽂아도 같은 이름이 됩니다 |
| 카메라 | 꽂은 USB 구멍의 위치 | `/dev/front` · `/dev/wrist` | 같은 모델 카메라 두 대도 구별됩니다. 대신 다른 구멍으로 옮겨 꽂으면 다시 저장해야 합니다 |

텔레오퍼레이션 · 데이터 수집은 이 고정 이름이 있으면 알아서 고정 이름으로 연결하고, 칼리브레이션 탭의 포트 목록에는 이 로봇의 고정 이름만 보입니다. 규칙 파일은 `/etc/udev/rules.d/99-<robot id>.rules` 에 생기고, 앱을 지워도 남습니다. 지우려면 5절의 **로봇 삭제** 를 씁니다.

### 4.4. 저장한 뒤 고치기 — 포트 편집 · 카메라 편집

저장하고 나면 고정된 칸이 잠기고(흐리게 보임) **포트 편집** · **카메라 편집** 버튼이 나타납니다. 카메라 칸이 잠긴 동안에는 **+ camera** 도 눌리지 않습니다.

<!-- 그림 필요: 저장 뒤 잠긴 로봇 설정 — 1. USB 옆 '포트 편집', 2. Camera 옆 '카메라 편집' 버튼이 보이고 칸이 흐린 상태 -->

1. **[앱]** **포트 편집**(카메라는 **카메라 편집**)을 누릅니다. 칸이 풀리고 안내 창(`포트 콤보에서 /dev/soarm-follower 같은 alias 를 선택하세요. …`)이 뜹니다. 창 속 이름은 예시입니다.
2. **[앱]** 포트 · 카메라를 고칩니다. 목록에 이 로봇의 고정 이름(`/dev/…`)이 보이면 그것을 고르고, `/dev/ttyACM*` 만 보이면 3.2절 팁처럼 한쪽만 꽂아 보며 어느 팔인지 확인해 고릅니다.
3. **[앱]** **로봇 저장** → 미리보기 **적용** → 관리자 비밀번호.

> **경고** ⚠️ `WARN`
> <br>**다시 저장할 때 팔로워 · 리더가 뒤바뀌지 않게** 카메라 이름만 바꿔도 **로봇 저장** 은 지금 골라 둔 포트(`/dev/ttyACM0` 같은 번호)에서 두 팔 보드의 번호를 다시 읽어 규칙을 새로 씁니다. 그래서 매번 두 팔의 USB 가 꽂혀 있어야 하고, 관리자 비밀번호도 매번 묻습니다. 케이블을 다시 꽂았거나 PC 를 다시 켠 뒤에는 `/dev/ttyACM*` 번호가 서로 바뀌었을 수 있습니다. 그대로 저장하면 팔로워 · 리더의 고정 이름이 뒤바뀌어 엉뚱한 팔에 명령이 갑니다. 저장 전에 **포트 편집** 을 누르고 3.2절 팁처럼 어느 포트가 어느 팔인지 확인해 다시 고르세요.

## 5. [앱] 로봇 삭제

### 5.1. 로봇 설정 탭에서 지우기

1. 지울 로봇의 **로봇 설정** 탭에서 **로봇 삭제** 를 누릅니다.
2. `이 로봇의 설정을 모두 삭제하시겠습니까? udev 룰 파일과 LeRobot 캘리브레이션 JSON 도 함께 제거됩니다.` 에서 **Yes** 를 누릅니다.
3. 규칙 파일이 있으면 관리자 비밀번호를 묻습니다.
4. `로봇 설정을 삭제했습니다.` 가 뜨고 로봇 창고로 돌아갑니다.

### 5.2. 로봇 창고에서 여러 대 지우기

1. 로봇 창고 오른쪽 위 **− 로봇 삭제** 를 누르면 카드마다 체크 동그라미가 생깁니다.
2. 지울 카드를 고르고 **선택 삭제 (N)** 을 누릅니다. 그만두려면 **취소**.
3. `선택한 N 개 로봇 설정과 udev 룰 파일, LeRobot 캘리브레이션 JSON 을 삭제합니다. 계속할까요?` 에서 **Yes** → (규칙 파일이 있으면) 관리자 비밀번호 한 번.
4. `N 개 로봇 설정을 삭제했습니다.` 가 뜹니다.

### 5.3. 지워지는 것 · 남는 것

> <br>**보정 파일도 함께 지워집니다** 같은 팔을 다시 등록하려고 로봇을 지우면 칼리브레이션을 처음부터 다시 해야 합니다. 포트나 카메라만 바꾸려면 지우지 말고 4.4절처럼 편집하세요.

## 6. [앱] 시리얼 포트 권한 창 (Ubuntu)

Ubuntu 에서 모터 보드(시리얼 포트)를 열려면 사용자가 `dialout` 그룹에 들어 있어야 합니다. Physical Labs `.deb` 는 설치할 때 사용자를 이 그룹에 자동으로 넣지만, **한 번 로그아웃했다가 다시 로그인해야** 적용됩니다. 그 전에 로봇 설정 탭 **모터** 칸(ID 셋업 마법사)의 **연결** 이나 단일 모터 테스트 · SO-ARM 101 전체 테스트의 연결처럼 모터 포트를 여는 버튼을 누르면 권한이 거부되고 아래 창이 뜹니다. 다른 탭(칼리브레이션 · 텔레오퍼레이션 등)은 이 창 없이 연결 실패 메시지만 보여 줍니다.

![시리얼 포트 권한 문제 창 — 자동 설정 · 수동 안내 탭, 사용자 · 포트 · dialout 가입 · 포트 모드 줄, 자동 설정 실행 버튼, 아래 다시 연결 시도 · 닫기](/img/physical_labs/serial-permission-dialog.webp)

*`시리얼 포트 권한 문제` 창. 그림의 사용자 `user` 는 촬영용 값입니다.*

1. **자동 설정** 탭에서 **자동 설정 실행** 을 누르고 관리자 비밀번호를 넣습니다. 앱이 `dialout` 그룹 가입과, 그 포트에만 주는 임시 권한을 한 번에 설정합니다.
2. `권한이 설정되었습니다. …` 가 보이면 **다시 연결 시도** 를 누릅니다. 지금은 임시 권한으로 바로 연결됩니다.
3. 시간이 날 때 **로그아웃했다가 다시 로그인**합니다. 그래야 그룹 가입이 영구로 적용되어 다음부터 이 창이 뜨지 않습니다.

창의 진단 문구 뜻, **수동 안내** 탭의 터미널 명령, 권한이 아니라 다른 프로그램이 포트를 쥐고 있을 때(`포트가 이미 다른 프로세스에서 사용 중입니다.`)는 [문제 해결](/docs/physical-labs/troubleshooting#시리얼-포트-권한)에 모았습니다.

## 7. 기종 · 운영체제에 따른 차이

### 7.1. SO-102 (7축)

| 다른 점 | 내용 |
|---|---|
| 예시 이름 | `예: my_so102` · `예: my_so102_leader` |
| 모터 | 팔마다 7개입니다. `ID 5 — Wrist Yaw (손목 좌우)` 가 새로 있고, 손목 회전(`Wrist Roll`) · 그리퍼(`Gripper`)가 6 · 7번입니다 |
| 모터 칸 | 마법사가 `Step 1/7` 부터 7단계로 진행합니다 |
| 리더 팔 | 리더도 7축 팔입니다 |
| 보정 파일 | SO-101 과 다른 폴더에 저장되어, 같은 이름이라도 서로 섞이지 않습니다 ([칼리브레이션](/docs/physical-labs/calibration)) |
| 탭 | **엔드이펙터** 탭이 잠깁니다 (`SO-102 기종은 이 기능이 아직 준비 중입니다.`) |

### 7.2. LeKiwi (A-Go)

**Lekiwi** 로봇은 팔로워 팔 · 바퀴 · 카메라가 로봇 안의 라즈베리파이에 붙어 있어서 칸 구성이 다릅니다.

| 칸 | SO-101 | Lekiwi |
|---|---|---|
| 맨 위 버튼 | **로봇 저장** · **로봇 삭제** | 그 왼쪽에 **로봇 다시 시작** · **로봇 종료** 가 더 있습니다 |
| 포트 | **1. USB** — 팔로워 · 리더 | **1. Leader Arm (USB-PC 직결)** — 리더만 |
| 로봇 연결 | — | **2. Lekiwi (원격)** — 로봇 주소 · 연결 방식 · **연결 확인** · **▶ 로봇 켜기** |
| 카메라 | **2. Camera** — PC 에 꽂은 USB 카메라 | **3. Lekiwi (카메라)** — 로봇의 전방 · 손목 카메라 |
| 모터 | ID 셋업 마법사 | 마법사 대신 안내 카드 |

리더 팔은 PC 에 꽂으므로 SO-101 과 똑같이 포트를 고르고 고정합니다. 리더 팔이 꽂혀 있어야 저장됩니다. 나머지 칸은 [Physical Labs 연결](/docs/a-go/physical-labs-setup) 문서에서 안내합니다.

### 7.3. Windows

> **정보** ℹ️ `INFO`
> <br>**Windows(최신 0.1.7)에서 다른 점**
>
> - 포트 고정(udev)이 없습니다. **로봇 저장** 은 미리보기 · 관리자 비밀번호 없이 설정만 저장하고, `Windows 에서는 USB 포트 고정(udev) 이 지원되지 않습니다. 장치를 다른 USB 포트에 꽂으면 COM 번호가 바뀔 수 있으니 가능하면 같은 포트를 사용하세요.` 라고 알려 줍니다.
> - 포트는 `COM3` 처럼, 카메라는 `카메라 0` · `카메라 1` 처럼 번호로 보입니다 (**새로고침** 뒤에는 `카메라 0  ·  640x480@30fps` 처럼 해상도도 붙습니다).
> - `시리얼 포트 권한 문제` 창이 없습니다.
> - SO-102 카드는 `준비 중` 이고, 새 A-Go(ROS 2 LeKiwi) 는 지원하지 않습니다.

## 8. 문제 해결

| 증상 | 확인할 것 |
|---|---|
| **로봇 저장** 이 흐려서 눌리지 않는다 | robot id · teleop id · **follower arm** 포트 · **leader arm** 포트, 네 칸이 모두 채워졌는지 봅니다 (이름 칸 · 카메라는 비어도 됩니다) |
| `robot id 는 영문/숫자/_/-/. 만 허용됩니다 ('…').` | 한글 · 띄어쓰기 · 다른 기호를 빼고 다시 저장합니다. 이름 칸이나 teleop id 가 규칙에 맞지 않으면 `leader arm: 이름은 영문/숫자/_/-/. 만 허용됩니다` 처럼 나옵니다 |
| `follower arm: /dev/ttyACM0 의 시리얼 넘버를 읽지 못했습니다.` | 그 팔의 USB 가 꽂혀 있고 보드 전원이 켜져 있는지 봅니다. 포트가 `(연결 안 됨)` 이면 **새로고침** 뒤 다시 고릅니다. 케이블 · USB 구멍을 바꿔도 같다면 보드가 고유 번호를 알려 주지 않는 경우일 수 있어, 이 PC 에서는 포트 고정(= 저장)이 되지 않습니다 |
| `카메라 이름을 입력하세요. 사용하지 않는 카메라는 ✕ 로 삭제하세요.` | 빨갛게 표시된 칸에 이름을 쓰거나, 그 카메라 줄을 **✕** 로 지웁니다 |
| `rules 작성이 취소되었습니다. 저장되지 않았습니다.` / `rules 작성이 실패했습니다. 저장되지 않았습니다.` | 미리보기에서 **취소** 했거나 관리자 비밀번호 창을 닫았습니다. **로봇 저장** → **적용** → 비밀번호를 다시 합니다 |
| `pkexec 가 시스템에 설치되어 있지 않습니다.` | 창의 안내대로 터미널에서 `sudo apt install policykit-1` 을 실행한 뒤 다시 저장합니다 |
| `설정 파일 저장 중 오류가 발생했습니다. rules 를 롤백했습니다.` + `이미 같은 robot id 가 있습니다: …` | 다른 로봇이 이미 그 robot id 를 씁니다. 다른 이름으로 저장합니다. 그 뒤 원래 로봇의 카드가 로봇 창고에서 사라졌다면 아래 줄처럼 원래 로봇을 다시 저장합니다 |
| 로봇 창고에 카드가 없다 (사이드바 **최근 로봇** 에는 있다) | Ubuntu 에서는 포트 고정 규칙 파일이 있는 로봇만 카드로 보입니다. **최근 로봇** 에서 그 로봇을 열고, 두 팔을 꽂은 채 **로봇 저장** 을 다시 하면 규칙이 다시 생깁니다 |
| 저장한 뒤 다른 탭에서 포트가 `(연결 안 됨)` | 안내대로 두 팔의 USB 를 한 번 뽑았다가 다시 꽂고, 그 탭에서 **새로고침** 을 누릅니다 |
| `미리보기 실패: 카메라를 열 수 없습니다: /dev/video2` | 다른 프로그램(화상 회의 앱 등)이나 다른 탭이 그 카메라를 쓰고 있지 않은지, USB 가 꽂혀 있는지 봅니다 |
| `미리보기 실패: 프레임을 읽지 못했습니다.` | 장치 목록에서 다른 번호를 골라 보거나, 카메라를 다시 꽂고 **2. Camera** 의 **새로고침** 을 누릅니다 |
| `카메라 미리보기` — `장치를 먼저 선택하세요.` | 카메라 줄 왼쪽 목록에서 장치부터 고릅니다 |
| 카메라 줄이 `/dev/video2  (연결 안 됨)` 인데 장치 목록에는 `cam_front  →  video2` 가 있다 | 같은 카메라입니다. `cam_` 으로 시작하는 이름을 쓰면 이렇게 보일 수 있고, 연결에는 문제가 없습니다. 신경 쓰이면 **카메라 편집** 에서 목록의 `cam_…  →  video…` 를 골라 다시 저장합니다 |
| 카메라를 다른 USB 구멍에 옮겨 꽂았더니 이름이 맞지 않는다 | 카메라는 꽂은 구멍 위치로 고정됩니다. **카메라 편집** 으로 장치를 다시 고르고 **로봇 저장** 합니다 |
| 연결할 때 `시리얼 포트 권한 문제` 창이 뜬다 | 6절을 따릅니다. 설치한 뒤 다시 로그인하지 않았을 때 흔합니다 |

모터 연결 · 응답 문제는 [모터 셋업](/docs/physical-labs/motor-setup), 그 밖의 문제는 [문제 해결](/docs/physical-labs/troubleshooting)을 보세요.

## 9. 정리

- 로봇은 **로봇 창고** › **+ 로봇 추가** 에서 기종을 골라 만들고, **로봇 저장** 을 눌러야 로봇 창고에 생깁니다.
- robot id 는 팔로워, teleop id 는 리더의 이름입니다. 보정 파일과 고정 포트 이름이 이 이름을 따르므로 처음 정한 뒤 바꾸지 않습니다.
- 포트는 두 팔을 꽂고 **새로고침** 으로 고르고, 이름 칸은 비워 둡니다. 카메라는 **+ camera** → 장치 · 이름 → **▶** 로 확인합니다. 해상도 · FPS 는 카메라 기본값을 씁니다.
- Ubuntu 에서 **로봇 저장** 은 USB 포트 고정(udev)까지 함께 합니다. 미리보기 **적용** → 관리자 비밀번호 → USB 다시 꽂기. 취소하면 아무것도 저장되지 않습니다.
- **로봇 삭제** 는 설정 · 규칙 파일 · 보정 파일을 함께 지웁니다.
- `시리얼 포트 권한 문제` 창은 **자동 설정 실행** → **다시 연결 시도**, 그리고 한 번 다시 로그인하면 해결됩니다.
